# noti-bridge 동기화 프로토콜

메시지 정의는 [proto/noti_bridge.proto](../proto/noti_bridge.proto) 에 있고, 프레임은 4바이트 빅엔디안 길이 + Protobuf 본문입니다. 최대 1 MiB입니다.

## 연결

- ALPN `noti-bridge/pair/1`: 페어링, `noti-bridge/sync/1`: 동기화.
- 기기 ID 는 iroh 공개키입니다. TLS 신원과 같으므로 별도 인증이 없습니다.
- 양쪽 다 연결을 시도합니다. 같은 상대의 연결이 둘이면 **ID 가 작은 쪽이 건 연결**만 남기고 다른 쪽을 코드 4409 로 닫습니다.
- 신뢰 목록에 없는 키의 동기화 연결은 코드 4403 으로 닫습니다. 페어링된 상대에게서 4403 을 받으면 상대가 해제한 것으로 보고 자신도 해제합니다. 단 페어링 후 60초 이내의 4403 은 상대의 저장이 끝나기 전일 수 있어 무시합니다.

## 페어링

1. 초대 기기가 `notibridge://pair?id=&relay=&token=&exp=&addrs=` 를 QR 로 표시합니다. 토큰은 1회용, 5분 유효입니다.
2. 참여 기기가 연결해 `PairRequest` 를 보냅니다. 토큰이 틀리면 연결을 끊고 토큰은 소모되지 않습니다.
3. 초대 기기가 `PairAccepted` 로 답하고, 양쪽이 두 공개키의 SHA-256 에서 만든 6자리 코드를 표시합니다.
4. 양쪽이 사용자 확인 후 `PairConfirm` 을 교환합니다. 둘 다 수락해야 신뢰 목록에 저장합니다.
5. 새 상대에게는 과거 로그 대신 현재 활성 알림 스냅샷을 보냅니다.

## 동기화

- 각 기기는 이벤트 로그를 순번(seq)으로 쌓습니다. 연결 직후 `Hello.last_seen_seq` 를 교환하고, 그 이후 이벤트만 보냅니다.
- 수신자는 이벤트 적용과 `last_seen_seq` 갱신을 한 트랜잭션으로 처리하고 `Ack` 를 보냅니다. 같은 seq 는 다시 적용하지 않으므로 답장·액션도 재전송에 안전합니다.
- `DismissRequest`, `ActionRequest`, `ReplyRequest` 는 원본 기기만 대상으로 합니다.
- 알림 게시는 원본 기기만 할 수 있습니다. `origin` 이 연결 상대와 다른 게시는 버립니다.
- 아이콘은 `IconBlob` 으로 해시당 한 번 보냅니다. 뒤따르는 이벤트의 Ack 를 받아야 전달된 것으로 기록합니다.

## 충돌 해결

`version` 은 Lamport 시계입니다.

- version 이 큰 쪽이 이깁니다. 같으면 dismissed 가 이깁니다.
- 원본은 `DismissRequest.version` 이 자기 version 보다 낮으면 요청을 무시합니다. 그 사이의 갱신이 상대에서 알림을 되살립니다.
- 삭제를 적용한 원본은 `Removed` 를 모든 상대에게 보내므로, 여러 PC 가 같은 상태로 수렴합니다.

## 보존

알림과 로그는 기본 24시간 뒤 삭제됩니다. 모든 상대가 Ack 한 로그는 더 일찍 지웁니다. 24시간 넘게 꺼져 있던 기기는 그 사이의 이벤트 일부를 받지 못하지만, 해당 알림도 보존 기간이 지나 함께 사라집니다.
